# 공식 보안 공지 자동 수집

[English and deployment commands](ADVISORY_AUTOMATION.md)

공식 PHP 공지를 주기적으로 모아 **별도로 구현할 작업 목록**을 만드는 서비스입니다. 기존 [공식 대응표](SECURITY_COVERAGE.ko.md)는 날짜가 고정된 검토 기록이며, 자동 수집 결과는 이후 변경을 추적합니다.

## 자동 처리 범위

- 공식 `php/php-src`의 공개 보안 공지를 모든 페이지에서 수집합니다. CVE가 아직 없는 공지도 GHSA 식별명으로 보존합니다.
- 새 공지·내용 변경·철회·목록에서 사라진 항목을 구분하고 이력을 남깁니다.
- 검토한 공지 내용과 PHP 소스 해시가 모두 일치할 때만 기존 판정을 인정합니다. 변경된 항목은 **구현 예정**으로 전환합니다. 자동으로 해결됨을 부여하지 않습니다.
- 전체 수집이 성공해야 D1 결과와 성공 시각을 함께 갱신합니다. 중간 실패 시 마지막 정상 결과를 보존하고 실패를 표시합니다.
- JSON과 Markdown을 기준으로 관련 소스 검토·구현·격리 시험을 별도로 진행할 수 있습니다.

[실제 구현 필요성 재검토](IMPLEMENTATION_NECESSITY.ko.md)를 반영한 현재 자료는 **66건: 수정 구현 2건 / 해당 결함 경로 부재 14건 / 검토·구현 예정 50건**입니다. 최초 배포 기록의 2/13/51은 당시 판정 이력으로 보존합니다. Ubuntu vendor 패치의 CVE는 기존 대응표에서 별도로 집계합니다. 이 분류가 모든 PHP 설치의 안전을 뜻하지는 않습니다.

## 로컬 배치

Node 24에서 `automation/advisory-sync`로 이동해 실행합니다.

```sh
npm ci
npm run check
npm test
npm run batch -- sync
npm run batch -- export --kind status
npm run batch -- export --kind backlog --format markdown
```

로컬과 Workers가 같은 TypeScript 처리 코드를 사용합니다. 기본 저장 위치는 현재 디렉터리의 `.work/advisory-sync`이며 `--state-dir DIR`로 전용 위치를 지정할 수 있습니다. 기존 일반 디렉터리·심볼릭 링크를 작업 상태로 덮어쓰지 않습니다. 내보내기는 읽기 전용입니다.

강제 종료로 로컬 잠금이 남으면 실행 중인 작업이 없는지 확인한 뒤 해당 `lock.json` 파일만 수동 정리합니다. D1 잠금은 120초 후 만료되며, 만료된 이전 작업이 결과를 게시할 수 없습니다.

## Workers 예약과 출력

Cloudflare 전용 Worker와 D1을 사용합니다. 사이트 도메인이 같은 계정에 없어도 `workers.dev` 주소로 운영할 수 있습니다. PHP 운영 서버는 변경하지 않습니다.

예약은 **매시간 정각**, Cron `0 * * * *`입니다. 설정은 UTC지만 한국 시각에서도 매시간 정각입니다. Cron 설정 전파에는 최대 15분이 걸릴 수 있습니다. 실제 예약 실행은 마지막 실행의 `trigger`가 `cron:0 * * * *`인지 확인하며 수동 성공과 구분합니다.

| 경로 | 내용 |
|---|---|
| `/status.json` | 마지막 시도·정상 수집 시각·소스/결과 해시·건수 |
| `/catalog.json` | 보존된 공식 공지 목록 |
| `/coverage.json` | 전체 판정과 검토 근거의 식별 정보 |
| `/changes.json` | 마지막 정상 수집의 변경 목록 |
| `/backlog.json` · `/backlog.md` | 구현 예정 작업만 제공 |

읽기는 공개되어 있으며 수집을 실행하지 않습니다. 수동 수집은 비밀 토큰을 사용하는 POST `/internal/sync`만 허용합니다. 계정·D1 UUID·토큰은 공개 저장소에 넣지 않습니다. [영문 배포 절차](ADVISORY_AUTOMATION.md#cloudflare-deployment)에 계정 선택·마이그레이션·비밀값과 함께 배포하는 방법을 정리했습니다. 요금제는 자동 변경하지 않습니다.

실제 Workers 실행에서는 GitHub 미인증 발신 IP의 잔여 한도가 0이어서 403이 발생했습니다. 안정적인 예약 실행에는 비공개 저장소·쓰기 권한이 없는 **전용 공개 읽기 토큰**을 선택적으로 `GITHUB_READ_TOKEN` 비밀값에 연결할 수 있습니다. 기존 CLI의 광범위한 토큰은 자동 복사하지 않습니다. [설정 방법과 공식 권한 근거](ADVISORY_AUTOMATION.md#shared-github-quota-and-optional-authentication)를 확인하세요. 토큰은 채팅에 보내지 않습니다. 제한 초기화 시각이 기록되면 그때까지 같은 인증 방식의 재호출을 억제합니다.

상태는 초기 자료만 있는 `NEVER_SYNCED`, 정상 `HEALTHY`, 성공 후 150분 초과 `STALE`, 최근 실패 `FAILED`입니다. 수집 실패 후에도 이전 정상 자료는 상태·시각과 함께 읽을 수 있습니다. 저장 자료 손상은 오류로 표시합니다.

## 이후 구현과 근거

구현을 마친 항목은 정확한 소스와 실증 근거를 기록하고 대응표를 검토한 뒤 초기 자료를 재생성해 반영합니다. 자동 수집만으로 해결됨·영향 없음 판정을 추가할 수 없습니다.

시험은 페이지 누락·중간 실패·제한 시간·동시 실행·만료된 작업의 게시 차단·실제 로컬 D1 트랜잭션·Worker 인증과 예약 처리를 확인합니다. 시험용 공지를 사용하는 런타임 검증과 실제 API·배포 서비스의 실행 근거는 구분합니다. 이력은 자동 삭제하지 않으므로 저장량과 계정 할당량을 관찰해야 합니다. PHP·OS·외부 라이브러리의 모든 시대 CVE 전체를 수집하는 것은 아닙니다.
